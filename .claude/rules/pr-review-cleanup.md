# PR 리뷰·커밋 정리 규칙

PR 리뷰, 커밋 정리, "커밋 묶어줘" 요청을 받으면 PR 마다 아래를 기본으로 함께 수행한다.
사용자가 반복해서 지시한 표준 절차이므로 따로 말하지 않아도 적용한다.

## 정리 범위

1. **유사 커밋 묶기**: 같은 기능의 후속·수정 커밋을 기능 단위 커밋으로 합친다.
   코드 커밋과 문서·평가 데이터 커밋은 나눈다.
2. **outdated 커밋 제외**: 뒤 커밋이 덮어써 최종 코드와 맞지 않는 중간 내용은 남기지 않는다.
   최종 상태만 기능 단위 커밋에 담는다.
3. **dead code 제거**: 런타임에서 호출되지 않는 함수·상수·설정을 지운다.
   테스트에서만 쓰이는 코드도 dead code 로 본다. PR 이 추가하지 않은 기존 코드는 범위 밖이다.
4. **테스트는 필요한 것만**: 상수값·argparse 기본값만 확인하는 테스트, 다른 테스트와 같은 내용을 검증하는 테스트를 지운다.
   결과를 바꾸는 로직, 적재·승급 가드, prod 차단 같은 안전장치 테스트는 남긴다.
5. **docstring·주석·문서를 최종 코드에 맞춤**: 삭제된 심볼 참조, 작업 이력 표현("Task N 에서", "기존엔"), 바뀐 동작 설명을 고친다.

## 절차

1. 정리 전 백업 태그 `backup/<branch>-before-squash-<YYYYMMDD>` 를 만들고 원격에도 push 한다.
2. 최신 base 브랜치로 rebase 한다. 충돌·base 변경 파일을 확인한다.
3. 정리 후 트리가 의도한 최종 트리(정리 변경만 차이)와 같은지 `git diff` 로 대조한다.
4. 커밋 경계마다 그 시점의 PR 관련 테스트를 실행하고, CI 와 같은 명령(예: `pytest -m unit`)도 통과시킨다.
5. `git push --force-with-lease=<branch>:<확인한 원격 sha>` 로 push 한다. 다른 세션이 같은 브랜치를 바꿨으면 멈추고 합친다.
6. PR 본문의 커밋 구성·테스트 수·검증 결과를 새 커밋 기준으로 현행화한다. 다른 사람이 쓴 본문 구성은 유지하고 필요한 부분만 고친다.

커밋 메시지 형식은 `commit-message.md` 를 따른다.
