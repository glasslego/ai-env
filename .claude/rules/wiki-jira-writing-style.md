# megan.won 문서 작성 규칙

- 긴 서술형 문단 대신 짧은 문장과 항목형 표현을 사용한다.
- 의미 단위마다 줄바꿈하고, 소제목·단락 간 여백을 둔다.
- 목록과 하위 항목 들여쓰기를 적극 활용해 관계를 드러낸다.
- 비교·계약·환경·일정은 표로 정리한다.
- 운영에 필요한 현재 정보만 본문에 남긴다. 중복 설명·지난 수치·옛 절차는 삭제하거나 이력으로 구분한다.
- 상세 구현·스키마·산식은 정본 저장소 링크로 연결한다.
- 위키는 Confluence Storage Format, Jira는 해당 스킬의 Jira Wiki Markup으로 의미 구조를 표현한다.
- 'megan.won 작성 스타일'은 위 형식 선호를 뜻한다. 작성자 계정 변경을 뜻하지 않는다.

## 적용 범위·우선순위

- Jira 본문·댓글·Epic, Agit 글, 위키, 코드 리뷰 결과, PR 본문, 커밋 메시지에 적용한다.
- 표현·분량·문서 구성은 사용자 지시 → 저장소의 구체적인 규칙 → 이 개인 규칙 → 팀 스킬의 기본 예시 순서로 적용한다.
- 팀 스킬의 API·인증·실행·검증·필수 필드와 문서 작성 스타일을 구분한다. 개인 스타일 적용을 이유로 권한·승인·안전장치나 필수 필드를 생략하지 않는다.
- cde-skills / cde-ranking-skills 원본은 develop을 유지한다. 개인 문체를 위해 팀 원본·플러그인 cache를 수정하지 않는다.

## 공통 정보 밀도

- 결과·문제·필요한 결정부터 쓴다. 한 항목에 한 사실, 하위 항목은 근거·조건만 담는다.
- 관련 없는 섹션, 같은 의미의 반복, 긴 배경 서사, 전체 티켓 목록·파일 목록을 자동으로 붙이지 않는다.
- 판단에 필요한 수치·조건·한계는 유지한다. 없으면 미정/미확인으로 구분하고 수치를 만들지 않는다.
- 정형 템플릿은 도구가 요구하는 최소 구조만 사용한다. 문서가 짧으면 표·목차를 억지로 만들지 않는다.

## Jira Epic

- 템플릿을 먼저 확인한다. 일반 Epic은 배경 → 목적 → 기대효과 → 성공 기준 → 완료보고 → 관련 링크의 `☑️` 헤더·순서를 유지한다. 제목 태그나 다른 헤더로 임의 교체하지 않는다.
- 인바운드 describe의 8개 헤더, 원장 관리 마커, 공유 항목의 기존 헤더·본문 구조도 유지한다. 간소화한다고 모든 모드를 일반 Epic 6섹션으로 바꾸지 않는다.
- 배경·목적은 각각 1~2개 항목, 기대효과·성공 기준은 판단 가능한 핵심 항목부터 쓴다. 증거가 더 필요할 때만 늘린다.
- 실제 붙은 라벨의 rubric 필드를 빠짐없이 간결하게 채운다. `- [label] field: value`는 들여쓰기·기호·필드명까지 파서 형식을 유지한다. 상세 근거는 링크로 연결한다.
- allow_unknown=false 필드는 실제 근거로 채운다. 미정 허용 필드만 미정으로 쓰고 숫자·완료 상태를 만들지 않는다. 라벨 없는 분야의 rubric은 자동으로 추가하지 않는다.
- 완료보고: 완료한 결과·검증·남은 제약. 미완료 Epic은 아직 완료되지 않았음을 짧게 표시한다.
- 담당자·상태·일정은 Jira 필드가 정본. 본문에서 반복하지 않는다. 단, roadmap:약속의 약속일정 등 rubric이 요구하는 필드는 생략하지 않는다.
- 상세 구현은 하위 Task/스펙 링크로 연결한다. 원장·위클리·서빙 카탈로그는 요청된 경우에만 확장한다.
- 개인 `epic-curator` 진입점을 먼저 사용한다. 선택한 모드의 팀 문서·CLI 도움말만 추가로 읽는다.

## Agit·리뷰·커밋

- Agit: 요청/결과 → 영향·확인 → 필요한 결정 → 근거 링크. 긴 회고·전체 작업 이력을 기본으로 붙이지 않는다.
- 코드 리뷰: 심각도·위치·발생 조건·영향·수정 제안을 짧게 적는다. 발견 사항이 없으면 검토 범위와 한계를 짧게 보고한다. 칭찬·체크리스트 전수 나열은 생략한다.
- PR: 구체적인 문제와 변경 후 동작 → 검증 → 필요한 운영 사항. abandoned approach와 대화 이력은 생략한다.
- 커밋: 저장소 제목 형식·Spec/Task 식별자를 유지하고 본문은 변경/입출력/검증의 짧은 목록으로 작성한다. 구체 형식은 commit-message.md가 정본이다.

## 토큰 사용

- 문서 작성 요청은 해당 문서·이슈와 직접 관련된 소스만 읽는다.
- 전체 스킬 목록·references·하위 티켓을 무조건 로드하지 않는다. 상세 절차는 선택한 모드에서 필요할 때만 읽는다.
- 리뷰·문서 초안은 본문만 반환한다. 수행 과정을 문서에 섞거나 최종 본문을 채팅에 반복하지 않는다.

## 위키 서식 기준 (2026-10-14)

- 사용자가 기준 페이지를 지정하면 제목 단계·본문·표 내부 서식까지 그대로 맞춘다. 제목만 맞추고 완료했다고 보고하지 않는다.
- 장보기 기준 문서: https://kakao.atlassian.net/wiki/spaces/CommerceDataEngineeringTeam/pages/246630294/Sandbox
- 표 본문은 일반 paragraph로 작성한다. 표 셀 안에 제목 태그, 코드 글꼴, 임의 font-size를 넣지 않는다. 헤더만 기준 문서처럼 굵게 표시한다.
- 기준 문서의 table layout, 전체 폭, colgroup 및 열별 폭도 복사한다. 전체 폭만 바꾸는 것은 서식 일치가 아니다.
- 저장 후 Storage와 atlas_doc_format을 다시 읽어 셀의 paragraph·marks·colwidth를 비교한다. 실제 화면을 보지 않았다면 시각적 일치를 확인했다고 표현하지 않는다.
- 짧은 항목과 표를 사용하고 중복 섹션은 합친다. 폰트·제목 크기를 임의로 크게 만들지 않는다.
