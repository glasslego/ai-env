# 완료보고와 주간 공유 형식

## Jira description

일반 Epic은 6섹션 중 `☑️ 완료보고`를 유지한다. Task는 다른 본문 구조를 유지하고 `h2. 완료보고`만 정확히 쓴다.

```text
☑️ 완료보고
* 결과: 소비처가 같은 배치 기준의 점수 파일을 사용할 수 있다.
* 근거: [구현 PR|실제 URL] develop 머지, [운영 검증|실제 URL] 확인.
* 확인 범위: 검증된 환경만 명시. prod 미확인이면 완료로 쓰지 않는다.
```

Task에서는 첫 줄만 `h2. 완료보고`로 바꾼다. 링크·결과는 실제 근거로 채운다. 위 항목명을 파서가 강제하지는 않으며, 내용이 짧으면 2항목으로 합쳐도 된다.

- 팀 `epic_report._section()`은 `☑️ 완료보고`, `h1.`~`h6. 완료보고`, `h2. ☑️ 완료보고`를 인식한다.
- 다음 헤더까지 추출한다. `완료 근거`·`구현 결과 및 검증`은 완료보고로 인식하지 않는다.
- 일반 Epic의 표준 구조 검증은 `☑️` 헤더를 요구하므로 새 문서는 canonical 표기를 사용한다.
- `TBD`·`미정`만 남기면 파서는 읽어도 실제 결과가 없는 보고가 된다.
- CDETEAM-160 같은 상시 운영 Epic은 완료보고를 생략하고 하위 Task에 결과를 남긴다.

## 최종 주간 공유 항목

Jira 완료보고를 읽어 합성하는 별도 출력 형식이다. Jira 본문에 아래 헤더를 강제하지 않는다.

```text
MM/DD (완료/진행/예정/이슈) 항목명 [jira] [agit]
- 배경 : 해결할 문제
- 목표 : 직접 제공·변경한 결과
- 기대효과 : 소비처 영향·필요한 조치
```

- 팀 `share-item-format.md`·`epic_report.render_entry()`가 정본이다.
- `label` 스타일은 배경→목표→기대효과 3줄, `impact`는 라벨 없이 영향 중심 2~3줄이다.
- PR·운영·공유 증거는 결과 판단 근거이며, 위클리에 4번째 `검증`·`남은 이슈` 불릿을 강제로 추가하지 않는다.

## 대상 선정은 별도 조건

- `leader-report collect`: 프로젝트의 Resolved Epic을 조회한다. description의 연결 Jira 이슈 resolutiondate 최댓값으로 이번 주와 회고성 종료를 나눈다. 완료보고 헤더만 고쳐도 자동 선정되지는 않는다.
- `person-collect`: 해당 주 담당자의 상태전이를 수집하고 부모 Epic으로 롤업한다. Task·Sub-task 활동을 포함하되 회고성 종료를 제외한다.
- 개인 위클리의 `완료`는 Epic 자체 resolution이 Fixed/Done일 때다. 하위 Task 완료, Closed/Won’t Do만으로 Epic 완료가 되지 않는다.
- 일반 Epic이 진행 중이면 하위 완료는 진행 근거로 사용한다. 상시 운영 Epic은 하위 활동으로 공유하므로 Epic에 완료보고를 다시 만들지 않는다.

## 확인 방법

팀 정본의 `scripts/epic_report.py`를 import하여 `_section(description, "완료보고")`가 정확한 절을 반환하는지 확인한다. 실제 포함 여부가 필요할 때만 `person-collect`/`collect` draft를 읽기 전용으로 확인한다. Jira·주간 문서 자동 게시·백업 댓글은 실행하지 않는다.
